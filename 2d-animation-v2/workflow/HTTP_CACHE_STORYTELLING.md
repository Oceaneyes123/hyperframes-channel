## What the baseline already does

The current `STORYBOARD.md`, `VISUAL.md` and `MOTION_OPTIONS.md` already specify
one continuous workshop, a retained notched image, independent freshness,
validator-only travel, a bodyless 304, a separate changed-response alternative,
camera restraint, secondary contact reactions and real holds. The board has
before/action/result poses for every line. It would be inaccurate to describe
this baseline as unrelated static cards or as lacking continuity and variation.

The opportunity is execution specificity: make the storage relationship visible
through an opened housing; distinguish local viewing from network transfer;
stage the validator comparison as a readable mechanism; vary composition through
the same workshop; and give every transition a concrete origin and destination.
These are planning improvements, not evidence that the resulting animation is
better. The baseline already has a OneTake composition, preview audit and render
report. No revised motion exists for this proposal; improvement over the baseline
has not been measured.

This direction applies the installed original `motion-design` checklist and its
`director/choreography.md`, `director/narrative-structure.md` and
`reference/property-selection.md`; OneTake's `references/motion-library.md`,
`references/rhythm.md` and current `lib/motion.js` establish implementation
feasibility. Mild confusion resolves into confidence; precise Corporate motion,
one hero action, position as the main property, zero rigid-body overshoot,
short mechanism gestures, smaller delayed support reactions and complete rest
remain the identity. Ambient motion stops during rests. UI timing tables guide
individual gestures, not the duration of spoken explanations.

## Stable world and representation boundaries

Use the existing storyboard's production IDs, not new identities at every line:

| Persistent object | Responsibility and allowed change |
| --- | --- |
| `housing-main`, `body-v7-main`, `notch-main` | Local storage and its retained image. Housing may open or reframe; the image and notch remain intact through expiry and 304. |
| `freshness-main` | Separate permission marker. Its labeled state changes; it never damages pixels. After validation, use the existing **Prior expiry** label, not an unsupported promise of renewed freshness. |
| `validator-v7-main`, `request-main` | Saved illustrative ETag value and a request carrying that value. Original stays associated with storage; request is a distinct carrier. Neither is the image, a security token or a whole-page checksum. |
| `server-current-main`, `reply-304-main` | Server-side current-version comparison and a status/metadata-only reply. A 304 carries no new image body. |
| `display-main` | A local view supplied by `body-v7-main`, with explicit source provenance. Revealing it does not move the stored body out of storage or download a second body. |
| `housing-alt`, `body-v7-alt`, `server-v8-alt`, `request-alt`, `reply-200-alt`, `incoming-v8-alt`, `body-v8-alt`, `display-alt` | Existing explicitly alternative scenario. New body retains arrival-to-storage provenance; v7 is never renamed v8. Main v7 stays as the unchanged-path witness. |

## Same speech, actionable decisions

All offsets are **estimated event windows relative to future measured phrase
cues**. `q + 0.0–0.3 s` means a proposed gesture after that cue, not a measured
timestamp. Hold targets are proposals to fit after natural delivery is known.
Dependencies outrank estimates: a reply cannot precede request arrival; local
reuse cannot precede the validation response in this illustrated stale path.
Animator measures/listens to cloned-voice WAVs after Gate 1 and records actual
cues in `motion_beats.json`. If events cannot fit clearly, return to the Director;
do not accelerate speech, overlap causes or claim synchronization. There is no
total runtime or automatic 180-second fit claim here.

### Line 1 — contradiction before spectacle

> This browser's image copy expired. So why is it still here?

- **Before → trigger → action → result/hold:** Start with intact notched v7 and
  expired freshness already visible. At “expired,” slide only the orange tab
  along its rail, `q + 0.0–0.25 s`; the rail shadow follows 0.05 s later. At
  “still here?” give the body a small camera recenter over 0.45–0.7 s, then
  hold the contradiction for a proposed ≥2.5 s. No pulse repeats the question.
- **Composition/carry:** Image dominates a close frontal lightbox; marker stays
  in view. The same housing lip opens into line 2, so the next explanation grows
  from the object just questioned. OneTake: scalar `tween`/`lerp`, `expoOut`;
  `camera` with `sineInOut`. Do not inflate the body to manufacture emphasis.

### Line 2 — reveal the relationship inside the same object

> Because expiration ends its freshness, not its existence. A browser cache can keep a stored response, including the image.

- **Before → trigger → action → result/hold:** Same stale body in housing. At
  “freshness, not its existence,” the tab shifts aside 24–40 px over 0.3 s while
  the body stays parked. At “stored response,” open the existing housing's lip
  into a shallow cutaway over 0.6–0.9 s: image sits inside a storage boundary;
  the tab occupies a separate rail. Hold both roles still for ≥1 s.
- **Composition/carry:** This is a mechanical reveal, not a second cache card.
  A restrained pullback exposes storage depth without moving image content.
  `morphRect` changes housing geometry, `tween` lifts its lip; `camera`/`view`
  may give the backing plane less displacement only during the pullback. All
  technical labels share the readable focus plane. That same open housing
  supplies line 3's local viewing aperture.

### Line 3 — local reuse through an aperture, not a flying image

> If the rules allow it, a fresh copy can be reused without checking with the server. That saves another transfer of the image.

- **Before → trigger → action → result/hold:** Preserve body; identify **Fresh
  case** before changing the tab, explicitly introducing an explanatory state.
  At “reused,” slide open the local-display aperture over 0.3–0.45 s to reveal
  the matching source image. Stored body stays put; display has
  `source=body-v7-main`. At “without checking,” hold the idle server and absence
  of a request; do not add a crossed-out network trip as a new competing action.
- **Composition/carry:** Local source/display dominate vertically within the
  workshop; idle server is readable but subordinate. No extra picture flies
  between storage and display. Use `tween` on the aperture and a static source
  view, not `hop`. Pause ≥1 s after opening. Aperture and body remain for line 4;
  a proposed 0.25 s aperture closure suspends this view before the stale check.

### Line 4 — state transformation with deliberate image stillness

> But once this copy becomes stale, the browser may need to check before reusing it. Stale doesn't mean deleted.

- **Before → trigger → action → result/hold:** Fresh marker, intact body, local
  display suspended. At “stale,” slide the existing marker through its rail to
  expose its Stale face over 0.2–0.3 s. The tab drives a tiny rail-shadow response
  0.05–0.1 s later. At “doesn't mean deleted,” **nothing happens to the image**;
  a ≥2.5 s true hold is the evidence. No image tint, fade, crumble or repair.
- **Composition/carry:** Fix the camera for the state comparison. The open
  housing still explains retention. `tween`/`expoOut` drives only marker/rail.
  As the sentence ends, the existing saved-validator edge beside that body
  becomes the next focal object; do not introduce a separate ETag diagram.

### Line 5 — a value detaches for travel; its source does not

> For this example, the server gave the image an ETag: a label for that version. The browser sends that saved label in a conditional request.

- **Before → trigger → action → result/hold:** Saved `ETag "v7"` is associated
  with retained image; identify the label for ≥1 s. This is existing metadata,
  not a newly staged image download. At “sends,” expose the same value inside
  `request-main`; original label stays local. Dispatch that carrier through an
  explicit bend/midpoint then to server over a proposed 0.7–1.2 s after the cue.
  Land and stop before comparison. Body stays still for the whole journey.
- **Composition/carry:** Reframe into the baseline's safe neutral wide **before**
  launch, showing cache and server simultaneously. Use two `hop` legs with
  shallow arcs if useful, or keyed `tween` position; each segment respects
  ≤360 px horizontal / ≤640 px vertical travel before a waypoint change.
  No camera chase while proof objects occupy the full width. Arrived request
  persists directly into line 6; it is not reset or resent.

### Line 6 — make comparison legible, then stop

> It's asking, “Does your current image still match this version?” The request carries the label; it doesn't send the saved image back.

- **Before → trigger → action → result/hold:** Request has arrived. At “match,”
  slide its readable v7 alongside server-current v7 over 0.25–0.4 s; a small
  server-shelf comparison bracket closes only after alignment. This is a visual
  explanation of server comparison, not a literal HTTP question string or a
  checksum scan. At the negation hold label at server and body at cache for ≥1 s.
- **Composition/carry:** Static wide, no split into unrelated panels. Only
  aligned value/bracket moves; no camera zoom hides the retained image.
  Use `tween`/`expoOut`, optionally `morphRect` for bracket bounds. Do not type
  v7 character by character or make it rotate while read. Completed alignment
  supplies line 7's visible cause; no receipt appears before it.

### Line 7 — small reply, then local reveal

> If the version still matches, the server can reply “304 Not Modified.” No new image body comes with that reply, so the browser reuses its stored body.

- **Before → trigger → action → result/hold:** Match is held. At “304 Not
  Modified,” the server releases a status/metadata receipt; return it through
  a waypoint over 0.7–1.2 s. Receipt has no picture, picture-shaped placeholder
  or hidden body. On arrival, a brief contact-shadow response settles. Only
  then, at the aligned “reuses” cue, reopen line 3's local aperture over
  0.3–0.45 s, displaying the same sourced v7. Hold receipt, source and local
  result together ≥2.5 s; marker identifies prior expiry, not assumed freshness.
- **Composition/carry:** Static wide for cause/reply/reuse; original source
  remains visible, unoccluded. Use keyed `hop`/position and `tween`, no receipt
  inflation into an image. The housing's lower edge then shifts to make room
  for line 8's alternative drawer; do not dissolve the completed main result.

### Line 8 — a distinct branch physically opens from the shared workshop

> If the image has changed instead, the server can reply “200 OK” with the new image. The browser can store that response and use the replacement.

- **Before → trigger → action → result/hold:** Main unchanged result remains a
  still readable witness. At “instead,” open a labeled **Alternative: changed**
  demonstration drawer from the shared housing/workbench over 0.6–0.9 s.
  It contains distinct alternate saved v7 and server-current v8. Establish
  alternate conditional-request arrival/comparison before its reply; never
  turn main 304 into 200. At “200 OK,” move its new visibly different v8 body
  with its response through a midpoint over 0.8–1.2 s. **Only on arrival** may
  alternate v7 yield its slot and incoming v8 become stored `body-v8-alt`.
  Then reveal its sourced local view. Hold old/new distinction before departure
  and replacement result ≥1 s. Fit is unverified; these actions may require
  longer natural cue spacing than the estimates.
- **Composition/carry:** Shared housing edge opens the branch; separate label
  precedes action. Use `morphRect` on its drawer, `tween`/`hop` for transfer,
  `expoOut` landing. Never morph v7 pixels into v8 or use error shake/red alarm
  for a valid 200 outcome. Keep main witness ≥240 px and alternate hero large;
  recompose planned geometry rather than shrink two entire boards. Art must
  verify this proposal at phone size before it replaces any selected pose.

### Line 9 — qualification gets room, not another demonstration

> These are permitted cache paths, not a rule for every request or reload. Cache instructions and whether the copy is still stored matter.

- **Before → trigger → action → result/hold:** Both cases are explicitly
  separate. At “permitted,” one small selection moves to the existing
  permission tab; at “still stored,” attention rests on the intact main body
  inside storage. No checkmark declares universal success. Let the alternative
  drawer recede within the shared workshop while its contents retain identity;
  do not turn alternate v8 into main v7. One 0.45–0.7 s reframe is sufficient,
  then ≥1 s stillness through the qualification.
- **Composition/carry:** Pull attention back to the original main housing and
  prior-expiry marker. `camera`/`sineInOut` carries the return; all ground and
  shadows stop. No eviction sequence, dashboard of directives, flashing warning
  or repeated request. Retained body and match receipt carry into the answer.

### Line 10 — earned answer as a resolved image

> So an expired copy can still be useful. A matching server check can let your browser reuse the image it already has.

- **Before → trigger → action → result/hold:** Return explicitly to **Unchanged
  path**, original notched body, prior-expiry marker and matching 304 evidence.
  At “already has,” keep the sourced local display open; it need not animate
  again. If source relationship was lost during reframing, use one 0.3 s
  aperture reveal, never another request. Settle fully before a proposed ≥3 s
  ending hold, retaining the complete natural spoken tail.
- **Composition/carry:** Close to the opening's image-and-tab relationship,
  now with earned matching-check evidence. `camera` ends on a fixed key;
  all objects become constant. No end card, logo, CTA or claimed seamless loop.
  Deliberate stillness makes the answer available to read and remember.

## Verified OneTake mappings; implementation still pending

These exports/signatures were checked directly in the installed
`C:/Users/Dave/.codex/skills/onetake/lib/motion.js` (`version: 1.1.0-lite`), in
addition to the original reference files. They are library feasibility evidence,
not an executed composition or a measured motion-quality result.

| Intent | Existing library API | Application boundary |
| --- | --- | --- |
| Tab, lip, bracket or aperture change | `OM.tween(t,t0,t1,OM.ease.expoOut)` and `OM.lerp(a,b,k)` | Returns numbers; Animator applies them to the same object's transforms. Text state remains explicit. |
| Housing/cutaway/drawer changes shape | `OM.morphRect(t,t0,t1,A,B,{curve:OM.ease.sineInOut})` | A/B are `{x,y,w,h,r}`. Transform the container, never image-to-tag or v7-to-v8. |
| Request/receipt curved segment | `OM.hop(t,t0,t1,from,to,{height,curve})` | `from`/`to` are `{x,y}`; height controls arc. Stage two segments around a waypoint; no implied network latency. |
| Purposeful framing and shallow backing depth | `OM.camera(t,keys,{W:1080,H:1920})`, `OM.view(cam,{W:1080,H:1920,depth})` | Keys include `t,x,y,zoom,rot,curve`; use `sineInOut` for calm reframes, fixed keys for holds. Safe wide stays fixed during proof. |
| Screen-space bounds and motion | `OM.projectBox(M,box)`, `OM.screenTravel(c0,c1,cMid,{W:1080,H:1920})` | Include camera movement and each relevant depth in `__track`/`__motion`; library defaults are landscape. |

Verified `ease.expoIn` supports departure accents; `ease.expoOut` supports clean
landings. Do not invent custom springs/easing or add Lottie, GSAP, CSS animation
clocks or another renderer. No need here for `whip`, `iris`, `zoomThrough`,
`gather`, `seal`, perpetual `drift` or decorative impact: they obscure the retained
body or imply an unrelated finale. Varied teaching actions matter more than
library-move count. Original skill contact sheets must still be inspected by
the responsible specialist when selecting final move parameters.
