# DeepSeek redesign: baseline audit

Inspected the actual existing 70-second MP4 through seven sampled rendered frames, the accepted script, all seven source drawings, motion authoring script and production receipt. Baseline: `before-contact.png`. Original artifacts remain immutable.

## Problems

1. Every shot reserves the upper half for the same generic person and horizontal bar. The salon is never recognizable. No expression, workplace or incoming-inquiry pressure explains the owner's problem.
2. Repeated document/browser/chip glyphs substitute for question content, reference material, software and a sellable service. Their similar silhouettes obscure different meanings.
3. Most action occupies a narrow band around the lower middle. Large dead areas weaken the focal hierarchy. Flat pale backgrounds do not create depth.
4. Product names sit beneath generic browser outlines. Sheets has no meaningful row, n8n no trigger or HTTP operation, and structured output no category/reply fields.
5. The owner-review boundary is a label and colored line. It lacks an actual draft, editing decision or unresolved-information path.
6. The existing energetic preset work provides entrances and emphasis, but the repeated layouts limit meaningful visual transformation. The final 18 seconds need multiple explanatory states.

## Direction: The Working Studio

Original editorial illustration using deep pine, warm paper, coral and mint. Detailed layered salon environments, expressive owner, desk objects, cutaway software and large editable typography. Alternate wide environment, overhead desk, stacked interface, cinematic processing, close review, opposing tests and presentation/handover. Keep one clear action per beat.

Use the installed curated vector JSON importer. Each original asset has immutable @1 identity, source, license, content hash and named animation layers. Text remains editable. Product interfaces are explanatory reconstructions, not screenshots or evidence of a connected live automation. Preserve all existing claims and narration.

## Approval boundary

The brief requests preservation of the approval workflow. New storyboard approval must therefore precede connected motion generation; existing approvals do not approve the redesign. `server/motion-store.ts` requires acceptance of the exact current storyboard. Prepare and inspect complete styleframes and save the proposed storyboard first. Do not manufacture acceptance events or production gates.
