## 1. finance-recovery

Why losing 50% and gaining 50% do not cancel

Payoff: Understand that percentages use a changing starting amount.

Required facts:
- Hypothetical 100 becomes 50 after a 50% loss.
- A 50% gain on 50 adds 25, reaching 75.
- Returning from 50 to 100 requires a 100% gain.

Limits: Ignore fees and deposits explicitly. No predictions, recommendations or promised returns. Use only supplied facts and explicitly hypothetical examples. Connect the opening promise to a useful ending. No invented demand, clients, sales, personal experience or income promises. Sparse overlay text only when it teaches. No forced CTA or generic motivational ending. Preserve uncertainty and permission requirements.

### A

1. If a hypothetical 100 loses 50%, why doesn’t a 50% gain bring it back?

2. The reason is that each percentage is calculated from the amount you have at that point.

3. Ignoring fees and deposits, a 50% loss on 100 takes away 50, leaving 50.

4. Now the starting amount is 50. A 50% gain on 50 adds 25, bringing the total to 75.

5. To get from 50 back to 100, the increase needs to be 50. Since 50 is the full starting amount, that increase is 100%.

6. So the percentages don’t cancel: the loss is measured from 100, and the gain is measured from the smaller amount, 50.

### B

1. If a hypothetical 100 loses 50%, why doesn’t a 50% gain bring it back?

2. Each percentage is calculated from the amount you have at that point. Ignoring fees and deposits, a 50% loss from 100 takes away 50, leaving 50.

3. Now calculate a 50% gain from 50. Half of 50 is 25, so the amount reaches 75.

4. The percentages are the same, but they use different starting amounts. The loss is calculated from 100; the gain is calculated from 50.

5. To get from 50 back to 100, you need to gain 50 on a base of 50. That requires a 100% gain. This is hypothetical arithmetic, not a prediction or recommendation.

## 2. http-cache-image

How a cached image can avoid another download

Payoff: Distinguish a local stored copy, freshness permission and validation.

Required facts:
- Expiry does not itself delete the stored image.
- Under applicable cache rules, a fresh copy may be reused without a network request.
- For an unchanged validated representation, a 304 response has no new image body.
- Changed content can require a new response body.

Limits: Do not generalize to every page or reload policy. No promise of renewed freshness after every 304. Use only supplied facts and explicitly hypothetical examples. Connect the opening promise to a useful ending. No invented demand, clients, sales, personal experience or income promises. Sparse overlay text only when it teaches. No forced CTA or generic motivational ending. Preserve uncertainty and permission requirements.

### A

1. If a cached image expires, does the browser delete it? Not necessarily.

2. Expiry alone doesn’t erase the stored copy. It affects whether that copy can be reused without checking.

3. Under applicable cache rules, a fresh copy may be reused without a network request. If it’s stale, the browser may need to validate it before reuse.

4. Think of the stored image as the copy, freshness as permission to use it without checking, and validation as checking whether it still matches.

5. If the representation is unchanged, the server can respond with a 304, which has no new image body. The browser may keep using its stored copy, subject to the applicable cache rules.

6. If the content has changed, the response may include a new image body. Expiry doesn’t mean deletion, and validation doesn’t always mean another image download.

7. The exact behavior depends on the page’s cache rules and reload policy. A 304 doesn’t guarantee the copy is fresh again.

### B

1. If a cached image expires, does the browser delete it? Not necessarily.

2. Imagine your browser has a saved copy of a product image. Expiry alone does not erase that copy.

3. Think of three separate questions: Is a copy stored? Is it fresh enough to reuse under the applicable cache rules? And, if it is stale, does it need to be checked with the server?

4. When the rules allow a fresh copy to be reused, it may be shown without a network request. Keeping a copy does not, by itself, mean it can be reused.

5. For a stale copy, the browser may validate it. If the representation is unchanged, the server can respond with 304, which has no new image body. The stored copy can then be used.

6. If the image has changed, a new response body may be needed. A 304 does not guarantee renewed freshness in every case; reload directives and other cache conditions can affect what happens.
